Action Packs

An Action Pack is the compiled binary runtime form of a workspace. The extension executes Action Packs, not workspace source files.

Compilation

Compilation validates required connections, block compatibility, regex safety, risk metadata, permissions, schema version, and Run details. A valid workspace can be compiled and exported from the editor or Manage Resources.

Action Pack schema 5 supports input-data triggers, hotkey-specific packs, remote data blocks, media/display blocks, logging, aborts, and event-driven overlay handlers.

Import Review

Imported Action Packs open in the staging gate. The gate shows metadata, risk warnings, plain-language behavior steps, and an interactive sandbox before the Confirm Import button unlocks.

Action Packs cannot run imported JavaScript. They execute only the compiled instruction types that URL Alchemist knows how to validate, explain, and run.

If a legacy .urlpack is imported, URL Alchemist converts it into an editable workspace instead of forcing you to recreate it manually.

Logs

Each installed Action Pack has a local log in Manage Resources. Every run records a timestamp, exit code, handler, issue count, and URL summary.

The Save string to log block writes a formatted entry with a severity level. You can view, export, or clear a pack log from Manage Resources.

Logs stay local and rotate automatically: URL Alchemist keeps the newest 300 entries or about 256 KB per Action Pack, whichever comes first.

Pairing

Manage Resources draws a connection between an installed workspace and any installed Action Pack compiled from it. You may delete either resource independently.

Overlay Interaction

Overlay examples compile to the same Action Pack format. A pack can request input capture only through known overlay instructions, and event-driven keyboard, mouse, and tick handlers run only while a URL Alchemist-owned overlay session is active.

The staging review shows these overlay and event instructions as normal compiled behavior. They are generic primitives, not hidden game-specific runtime code.

Sharing

Share a .workspace when you want someone to edit or inspect the source graph. Share a .actionpack when you want a compact runtime package that still goes through staging before install.

Chrome and Firefox use the same binary artifact formats. If an imported Action Pack uses a browser capability that Firefox does not support or has not verified on Android, the staging gate shows that compatibility note before install.
