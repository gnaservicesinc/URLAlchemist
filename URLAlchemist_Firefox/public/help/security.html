Security

URL Alchemist treats imported Action Packs as untrusted bytecode. Validation recomputes risk and permission metadata from the compiled instructions instead of trusting wrapper claims.

The extension does not use eval or downloaded code to run a pack. Every runtime behavior must map to a known instruction produced by the compiler and accepted by validation.

Tracing

Tracing records local execution steps and issues for selected installed Action Packs. The Security tab explains audited files in plain language so you can see what a pack reads, writes, changes, or sends before enabling it.

Action Pack Logs

Per-pack logs are local records of runs and explicit Save string to log entries. They can include URLs or strings chosen by a workflow, so export or share them with the same care as trace files.

New Action Packs default logging off. Migrated existing packs keep logging on until you turn it off in Manage Resources.

Use Clear Log in Manage Resources when a pack log no longer needs to be retained. Older entries are also pruned automatically after the newest 300 entries or about 256 KB per Action Pack.

Hardening

Hardening settings can reduce VM instruction count, redirect recursion, and regex timeout limits. They cannot loosen the built-in default safety budgets.

Remote data and asset blocks require HTTPS, reject credentials, and block private, local, and reserved network hosts. Local file:// navigation is disabled by default and controlled from Settings.

Page text, raw HTML, and page-link reads are capped before leaving the content script so unusually large pages cannot create unbounded runtime payloads.

Clipboard, raw page, remote request, and page mutation behavior should be reviewed carefully before installing a pack.

Keyboard or mouse capture and real-time overlay events are allowed only through overlay blocks that URL Alchemist owns. Review these packs carefully and close the visible overlay to stop capture and event routing.

Focus Guard Locks

Focus Guard installs content-blocker rules as normal Action Packs with extra local metadata. Locked packs cannot be disabled, deleted, exported, overwritten by rebuild/import, or removed through backup restore or full reset until unlocked.

Level 1 locks require challenge text, repeated confirmation, and a delay. Level 2 locks verify a password with salted PBKDF2 through WebCrypto. Level 3 locks have no in-app unlock path.

Locks are enforced inside the extension and browser APIs. They cannot prevent extension removal or direct browser profile tampering.

File Audit

The Security tab can inspect an uninstalled workspace or Action Pack and report validation, permissions, risk reasons, Run plan, and plain-language steps without saving it.

Sandbox Model

Action Packs are treated as untrusted bytecode. The import flow stages the decoded pack in memory until you review it, test it in the sandbox, or explicitly mark the logic as reviewed.

Data Recovery

Chrome removes local extension storage when an extension is uninstalled. Use Settings to export a backup and the local builder UUID before release testing, reinstalling, or moving to a new browser profile.
