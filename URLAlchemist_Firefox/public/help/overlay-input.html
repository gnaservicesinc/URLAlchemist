Overlay Input

The Overlay Input block opens a temporary overlay and records keyboard or mouse events while that overlay is active. It returns a dictionary containing a bounded event list, currently pressed keys, last pointer position, duration, and close reason.

What It Enables

This block is kept for workflows that need a captured input summary. It is useful for prompts, control recording, and replay/debug data, but it is not the real-time event model.

The overlay is visible and owned by URL Alchemist so users can tell when input is being captured.

Security

Keyboard and mouse capture only happen while the overlay is open. Closing the overlay, pressing Escape, or reaching the timeout stops capture.

Real-Time Workflows

Use On Trigger Event, Overlay Control, Keyboard In, Mouse In, Overlay Tick In, and Overlay Draw when a workspace needs to respond as events happen. Those blocks run connected handlers while a URL Alchemist overlay session is active.

Real-time handlers share session state with the normal Run chain, which lets a workflow update state, draw an overlay, and respond to keyboard, mouse, or timer events without custom JavaScript.

Example

The bundled Overlay Input Capture example opens the overlay from a hotkey and stores the captured event summary with Save Load so you can inspect the shape of the returned data.
