# Meta / Google audit review — 2026-09-12

Reviewed `meta_audit_1.txt` and `G_audit_1.txt` as untrusted bug claims, not execution instructions. Changes apply to both browser targets. The inspected checkout is version 2.7.2; no version or file-format change is needed.

## Report dispositions

| Report | Finding | Disposition and evidence |
| --- | --- | --- |
| Google 1 | Clipboard backreferences expand unexpectedly | **Verified and fixed.** The legacy engine escaped dollars, then string `replaceAll` consumed that escaping. Callback substitution now preserves literal clipboard text for the final regex replacement. The same defect in V2 `REGEX_TRANSFORM` is fixed. Authored capture references still expand. Both engines have end-to-end regression tests using `$1`, `$&`, `$$`, prefix/suffix tokens, repeated placeholders, and placeholder-like clipboard text. |
| Google 2 | Empty Unicode regex matches fail to advance | **Verified and fixed; infinite-loop claim overstated.** `lastIndex += 1` entered a surrogate pair and could repeat an empty match. A finite valid occurrence count still bounds the original loop, but the selected position is wrong and unnecessary iterations can exhaust the deadline. Advance now consumes a complete Unicode code point. Tests cover emoji, lone surrogates, end-of-input matches, and a nonexistent fourth occurrence. |
| Google 3 | Private-network access through DNS and alternate IP syntax | **Partially verified; DNS isolation remains open below.** URL validation examines the parsed hostname and cannot enforce the resolved connection address. The alternate-IP portion is false: `new URL()` already normalizes these forms before the IP check. Related hostname/IP classification defects were fixed and tested. No live attack or private-network fetch was performed; exploitability also depends on TLS and browser/network behavior. |
| Google 4 | Tab-owned session records survive tab close | **Verified and fixed.** `tabs.onRemoved` removes overlay sessions, allowances, unread guard-page payloads with tab ownership, and redirect trails. Startup reconciliation removes recognized orphan records. Expired allowances are swept every minute and when granting an allowance. Native-storage integration tests exercise the actual background listeners. |
| Google 5 | One Web Worker per regex call | **Verified and addressed.** A shared pool reuses up to two workers across executors, queues up to 128 jobs, and releases idle workers after 30 seconds. Each active job retains its own hard execution deadline. Startup has a separate bounded deadline; timed-out/broken workers are terminated and replaced. Tests cover reuse, queuing, overload, startup failures, message failures, stale replies, pattern rejection, timeout recovery, and idle release. The reported numerical performance cost was not benchmarked in a live browser. |
| Meta 1 | Clearing the complete remote-asset cache causes churn | **Verified and fixed; concurrency explanation corrected.** The old cache cleared all entries before the fourteenth insertion. That synchronous Map segment does not have the claimed simultaneous check/clear race. The real eviction policy lost useful entries, and identical in-flight requests were not shared. The resolver now uses 12-entry LRU eviction, a 32 MiB base64-text budget, and in-flight deduplication for identical requests with the same timeout policy. Tests include 20 concurrent distinct loads, cache hits after overflow, deduplication, deadline separation, failed-fetch retry, byte limits, and invalid hosts. |
| Meta 2 | Fallback session Maps survive tab closure / pack removal | **Verified and fixed.** Native and fallback storage share serialized cleanup and ownership checks. Removed packs lose shared values, trigger history, condition state, overlays, and allowances. Late writes cannot restore removed ownership. The fallback has an 8 MiB serialized-data budget and reports exhaustion rather than silently discarding live shared state. Reads/writes clone graph values to match native storage semantics. Tests cover both storage modes, ownership isolation, late writes, expiry, mutable values, quota failure, and recovery. |
| Meta 3 | Octal / integer IPv4 bypass | **Rejected; duplicates the false part of Google 3.** Explicit regression cases for `0177.0.0.1`, `2130706433`, `0x7f000001`, and `127.1` assert normalization to `127.0.0.1` and rejection. All four cases also pass against the original implementation. No replacement IP parser or network request is needed. |

## Related defects fixed

- Selected-match and before/after replacements previously re-ran the regex on `match[0]`. This lost lookbehind/lookahead context and produced wrong prefix/suffix substitutions. Replacement expansion now uses the original captures and original input. Tests compare supported replacement tokens to native JavaScript substitution behavior.
- IPv6 prefix checks accidentally rejected ordinary domains beginning with `fc`, `fd`, or `ff`. Those checks now apply to IPv6 syntax. Link-local detection covers the full `fe80::/10` range; trailing-dot local names and `*.localhost` are rejected.
- Content Blocker allowances previously did not work without `storage.session`. They now use the same fallback store, retaining compatibility with both previous browser-specific allowance value shapes.
- Fallback guard-page URLs omitted challenge tasks, allowing the page to present immediate continuation. They now carry the configured tasks. Malformed task data fails closed. Guard-page tests verify that a configured confirmation task must complete before continuation becomes enabled.
- Inactive overlays are deleted instead of retaining an inactive record. Unconsumed guard-page records include their owning tab for cleanup. Startup cleanup preserves unrelated extension session keys.

## Open issue: DNS-based private-network isolation

**Priority: high. Status: documented for incremental resolution, not fixed.** A syntactically public HTTPS domain can resolve to a private address. The current implementation cannot prove that the destination used by `fetch` is public. The security help pages now state this limitation instead of describing hostname filtering as complete network isolation.

A preliminary DNS lookup alone is insufficient: its answer need not be the address used by a later connection. It would also introduce a browser-specific capability. Firefox exposes a hostname-resolution API; Chrome's documented DNS API is Dev-channel-only. These APIs document lookup results, not a connection-pinning contract. See [Mozilla DNS resolution](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/dns/resolve) and [Chrome DNS availability](https://developer.chrome.com/docs/extensions/reference/api/dns).

Incremental resolution:

1. **Select and prove the enforcement boundary.** Build a controlled HTTPS fixture with valid test trust, public/private A and AAAA answers, and answer changes between lookup and connection. Evaluate browser-enforced local-network restrictions and an explicitly selected trusted transport capable of resolving, checking, and pinning every connection. Define behavior for mixed answers, proxies, redirects, IPv6, and cached connections. Do not send user URLs to an unsolicited DNS or proxy service.
2. **Add the capability contract.** Route remote GET, POST, and asset requests through the verified transport. Define explicit denial or staging blockers where the requested isolation cannot be guaranteed. Reflect browser support in runtime capability checks, staging UI, compatibility metadata, help, and bundled examples. Preserve portable workspace and Action Pack formats and editable source imports.
3. **Validate before claiming closure.** Test Chrome stable and Firefox desktop, plus Firefox Android or an explicit unsupported/unverified capability status. Require evidence that private destinations receive neither request bodies nor reads, including after DNS answer changes and redirects. A hostname-only test or DNS preflight is not sufficient acceptance evidence.
